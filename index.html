One research loop.

API readiness is rarely a docs problem. It is an entitlement problem: whose account, which plan, what review, and whether a developer can act across customers.

The finding

Public API ≠ self-serve production access.

OAuth and scoped tokens are the dominant integration shape. The sharpest build blockers sit one layer above the endpoint: account/plan eligibility, admin consent, production review, and third-party distribution. Start with reversible read workflows; queue policy-heavy products for outreach.

Patterns to act on

Directional findings from an 11-app purposive accuracy sample. The separately source-checked rows have not been included in prevalence counts; the current fetch pass was blocked by workspace DNS.

01 / AUTH

OAuth + a second credential is common

Google Ads combines OAuth with a developer token. App installs commonly add scopes and tenant consent. API keys are simpler for single-account use; third-party distribution changes the design.

02 / ACCESS

Test access and production are different products

Google Ads has test versus production access levels; Plaid separates free Sandbox from reviewed production; Salesforce API access depends on edition and org permissions.

03 / BUILD

Buildability is an entitlement ladder

Rank candidates by source clarity, self-serve credential path, scope safety, and approval burden. LinkedIn Marketing and Amazon SP-API need review/roles; a local CLI can be a skill without a hosted API.

Agent workflow

A lightweight evidence locator turns the hundred sources into a structured queue. It does not pretend keyword matches are policy decisions.

Input

Category, purpose, docs entry point, initial auth/access hypotheses.

Fetch
Page signals

Human gate
Resolve ambiguity

Open official docs; distinguish sandbox from live, internal from third-party use, and docs from entitlement.

Output
Reviewable queue

Evidence URL + confidence label + blocker. Missing evidence stays “validate”; MCP is not inferred.
